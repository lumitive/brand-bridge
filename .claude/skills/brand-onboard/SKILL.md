# brand-onboard

Compresses the 5-day brand integration into ~half a day by generating the boilerplate.

## Phase 1 — gather

- `brand_id`, `brand_name`
- API docs source (OpenAPI URL / Postman JSON / docs URL / pasted text)
- API base URL
- Auth scheme (Bearer / API key / HMAC)

## Phase 2 — read the platform contract

Required reading before generating anything:
- `src/brand_bridge/core/providers/*.py` — the five ABCs
- `src/brand_bridge/core/types.py` — Pydantic models adapters must return
- `docs/INTEGRATION_GUIDE.md` — worked example

## Phase 3 — parse brand API

For each endpoint, extract: HTTP method + path, params, response schema, auth.

## Phase 4 — map

Match brand endpoints to ABC methods by:
1. **Semantic match** on path/operation name (`/stores/nearby` → `list_stores`).
2. **Param match** (`city` argument → `list_stores`).
3. **Response shape** (returns `calories` → `nutrition_info` candidate).

If a method has no candidate, set the relevant feature flag to `false` rather than guessing.

**Confirm the mapping with the user before generating code.**

## Phase 5 — generate

Write to `tenants/<brand_id>/`:
- `tenant.yaml`
- `master_data.py` (`<Brand>MasterData`)
- `pos.py` (`<Brand>POS`)
- `crm.py` (`<Brand>CRM` — or stub if disabled)
- `payment.py` (or pick a built-in adapter from `brand_bridge.adapters`)
- `test_adapter.py` (parameterized contract test)

## Phase 6 — verify

```bash
brand-bridge tenant validate <brand_id>
uv run pytest tenants/<brand_id>/test_adapter.py
```

If tests fail, inspect the diff between adapter return shapes and Pydantic models. Fix and retry — bound at 3 attempts before flagging to the user.

## Phase 7 — report

```
✅ Onboarded: <brand_name>

Generated:
  tenants/<brand_id>/tenant.yaml
  tenants/<brand_id>/master_data.py     (8/8 endpoints mapped)
  tenants/<brand_id>/pos.py             (5/6 endpoints — inventory disabled)
  tenants/<brand_id>/crm.py             (feature stars_mall disabled, no API match)
  tenants/<brand_id>/payment.py         (used built-in StripeAdapter)
  tenants/<brand_id>/test_adapter.py

Next:
  • Set MYBRAND_API_TOKEN in your env
  • brand-bridge serve --tenant <brand_id>
  • Wire to Claude Desktop via examples/claude_desktop.json
```

## Hard rules

1. Never modify platform code (`src/brand_bridge/`).
2. Adapter return shapes MUST match Pydantic models in `core/types.py`.
3. `confirmation_token` is generated by the platform helper — adapters call it inside `calculate_price`.
4. When a mapping is uncertain, ask the user. Do not guess API semantics.
5. Tests must pass before reporting success.
