# Provider Spec

Quick reference for every method on every Provider. For full type definitions see `src/brand_bridge/core/types.py`.

## MasterDataProvider

| Method | Purpose | Returns |
|---|---|---|
| `list_stores(*, city, keyword)` | Search stores | `list[Store]` |
| `get_store(store_id)` | Fetch one store | `Store \| None` |
| `list_categories(store_id)` | Menu categories | `list[Category]` |
| `list_products(store_id, *, category)` | Menu items | `list[Product]` |
| `get_product(product_code)` | One item with full detail | `Product \| None` |
| `list_modifiers(product_code)` | Customization options | `list[Modifier]` |

## POSProvider

| Method | Purpose | Returns |
|---|---|---|
| `calculate_price(*, store_id, items, coupon_code, pickup_type)` | Get price quote + confirmation_token | `PriceQuote` |
| `place_order(...)` | Place order (idempotent, token-gated) | `Order` |
| `get_order(order_id, user_id)` | Fetch order | `Order \| None` |
| `cancel_order(order_id, user_id, reason)` | Cancel order | `CancelResult` |
| `list_recent_orders(user_id, *, limit)` | Order history | `list[Order]` |
| `inventory_snapshot(store_id)` | Stock + low-stock alerts | `InventorySnapshot` |

**Confirmation token:**

```python
from brand_bridge.core.audit import generate_confirmation_token

async def calculate_price(self, ...):
    quote = await your_backend.quote(...)
    quote["confirmation_token"] = generate_confirmation_token()
    return PriceQuote(**quote)
```

`place_order` does not call your method until the platform layer has verified the token.

## CRMProvider

| Method | Purpose | Returns |
|---|---|---|
| `get_member(*, user_id, phone)` | Fetch member by id or phone | `Member \| None` |
| `list_campaigns(*, month)` | Active and upcoming campaigns | `list[Campaign]` |
| `list_available_coupons()` | Public coupon center | `list[Coupon]` |
| `list_my_coupons(user_id, *, status)` | User's wallet | `list[Coupon]` |
| `claim_coupon(user_id, campaign_id)` | Claim one | `ClaimResult` |
| `claim_all_coupons(user_id)` | One-shot claim-everything | `ClaimResult` |
| `store_coupons(store_id, user_id)` | Coupons usable at this store | `list[Coupon]` |
| `get_points(user_id)` | Points balance | `PointsAccount` |
| `redeem_points(*, user_id, product_code, idempotency_key)` | Redeem item | `RedeemResult` |
| `list_addresses(user_id)` | Delivery addresses | `list[Address]` |
| `create_address(...)` | New address | `Address` |

If your brand has no loyalty program, set `features.coupons: false` and `features.stars_mall: false` in tenant.yaml; these methods can `raise FeatureDisabled` (the platform handles it gracefully).

## PaymentProvider

| Method | Purpose | Returns |
|---|---|---|
| `create_prepay(*, order_id, amount, payment_method, subject)` | Pre-payment ID + sdk params | `PrepayResult` |
| `handle_callback(*, body, headers, provider)` | Verify + parse webhook | `CallbackResult` |
| `query_status(order_id)` | Pull status | `PaymentStatus` |
| `refund(*, order_id, amount, reason)` | Refund | `RefundResult` |

Maps 1:1 to lumi-agent's `PaymentService` interface; existing Alipay / WeChat Pay / Stripe code can be ported without method-shape changes.

## IMChannelProvider

One implementation per `(tenant_id, channel_kind)`. Channels register at startup; the platform routes outbound by channel kind.

| Method | Purpose | Returns |
|---|---|---|
| `parse_inbound(payload)` | Native webhook → `InboundMessage` | `InboundMessage` |
| `format_reply(reply)` | `AgentReply` → channel-native envelope | `OutboundReply` |
| `send(*, to, reply)` | Push outbound message | `dict` (provider response) |
| `verify_webhook(payload, headers)` | Signature check | `bool` |

## Common parameters

- `user_id` — derived from JWT scope (production) or `default_user_id` from tenant.yaml (demo).
- `idempotency_key` — supplied by the AI host. Platform dedupes; you may forward it as `Idempotency-Key` header.
- `confirmation_token` — generated by the platform inside `calculate_price`; verified by platform before `place_order` runs.

## Returning extra fields

Every Pydantic model has `model_config = ConfigDict(extra="allow")` plus a `metadata: dict` field. Use `metadata` for brand-specific extras you don't want to coerce into the canonical shape.

## Errors

Raise from `brand_bridge.core.errors`:

- `UpstreamError` — backend down or returned 5xx
- `ValidationError` — input failed brand-side validation
- `FeatureDisabled` — feature flag off
- `ConfirmationTokenError` — should be rare, platform usually catches
- `IdempotencyError` — same key, different body
- generic `AdapterError` for anything else

The platform translates these into user-visible MCP errors with appropriate scope.
